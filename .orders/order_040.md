# Order 040

## ユーザーの指示（原文）

今こんな感じでラベルをつけてるんだけど，媒体は維持したまま属性と形式のラベルを変更するか悩んでる

生徒は，
媒体（写真，マンガ，アニメ，テキストグラフィック，絵画，イラスト）を複数個
属性（カルタ記号あり，空欄あり，お題文あり，文字あり）を複数個
それぞれ予測する

生徒がお題文ありと予測した画像をQwenに入力し，
お題文ありか否かを予測する

Qwenがお題文ありと予測した場合，生徒の予測を用いる
お題文なしと予測した場合，生徒の属性の予測からお題文ありを取り除く

形式は属性に応じプログラムから決定する

これを判断するためにそれぞれのカテゴリに対するQwen，生徒，全プロセスの適合率，再現率を出す

## 指示の解釈

- 属性・形式のラベルの見直しを判断する材料として，お題画像の各カテゴリ（形式4，属性3，媒体7）の適合率・再現率を，次の判断者ごとに求める．新たな学習やラベルの変更はしない．
  - Qwen：Qwen3-VL-8B 単独で全てのラベルを付けた場合（生徒の教師ラベル T_v11）．加えて，確認の質問（お題文か）を全ての画像に行った場合の値も求める．
  - 生徒：確認の質問を反映する前の生徒の予測（パッケージの annotation.parquet の確率から再構成）．
  - 全プロセス：生徒＋Qwen の確認の質問（パッケージの最終の出力）．
- 実装との対応：パッケージの生徒は「お題文あり」を属性ではなく形式（4区分の1つ）として予測し，形式を優先順位（カルタ＞穴埋め＞お題文＞通常）で1つ選ぶ．
  そのため「お題文あり」は形式のお題文として評価する．目視のラベル（定義書 v4）にも属性のお題文ありはない．
  確認の質問が偽のとき，実装は「お題文以外で確率が最大の形式」にする．指示の構成（属性から形式を導く）との違いの影響を見るため，「属性から形式を導く」場合も模擬して比べる．
- 媒体にはゲームも含める（現行の定義書 v4 の7項目）．
- 正解は Claude Code の目視のラベル（定義書 v4）とする．
  - 実データ：無作為抽出160枚と層別抽出220枚を抽出確率の逆数で重み付けした推定値（ex009 と同じ方法）と，ブートストラップの95%区間．
  - 評価用データ640枚（少ない区分を多く含む）．
- プログラムは programs/ex023_image_label_pr/，結果は outputs/ex023_image_label_pr/ に置き，report_040 と PDF にまとめる．
