# Order 030

## ユーザーの指示（原文）

今回のClaude CodeのアノテーションやQwenのアノテーション，生徒モデルのアノテーションをLINEの公式アカウントを経由して判定することを考えます
この時，公式アカウントを実装してください．

まずは画像のアノテーションを判定します
アノテーター(QwenやClaude，生徒モデル)の付与したアノテーションと画像を見せ，ユーザーは一致する，一致しない，判定できないかを選択します
画像とボタンを一緒にして表示すると良いでしょう

この際，ユーザーが評価する前に，軸の形式や媒体の説明と例示，年齢・性別のような簡易的なバックグラウンドの確認をはじめにします
また，明らかに誤ったアノテーションと画像のペアを不定期で挟み，ユーザーが適当に評価していないかを確認します

サーバーはCloudflareの無料枠経由でLINEと接続する予定です

このプログラムはカレントディレクトリ以下に，
Bokete_LINE_Annotatorというリポジトリを作成し，この中で実装してください
今回作成するのはBoketeImageAnnotatorとしてください．
将来的には大喜利を評価するBoketeSentenceAnnotatorを作ります

## 指示の解釈

- プロジェクトルートに独立した Git リポジトリ `Bokete_LINE_Annotator/` を作成する（`Bokete_Annotation_programs_v5.0/` と同様に本体の `.gitignore` に加える）．
  その中に `BoketeImageAnnotator/` を実装し，将来の `BoketeSentenceAnnotator/` と共有できる部分（LINE の署名検証・返信，同意，属性の質問，注意確認の出題の間隔）は `shared/` に分ける．
- サーバーは Cloudflare Workers（無料枠）とし，状態と回答は D1（SQLite），画像は Workers の静的アセットで配信する（R2 を用いずに無料枠で完結させる）．
  LINE の無料のプランではプッシュメッセージの通数に上限があるため，全てのやり取りを応答メッセージ（reply）で行う．
- 判定の対象：定義書 v4 のラベルが Claude Code（目視），Qwen（教師 T_v11，Qwen3-VL），生徒モデル（パッケージの最終版）の3者で揃っているお題画像1,020枚．
  判定の単位は「画像×軸（形式・属性・媒体）×ラベルの値」とし，複数のアノテーターが同じ値を付けた場合は1問にまとめ，結果を各アノテーターに対応付ける．
  アノテーターの名前は評価者に示さない（盲検）．
- 1問は，画像（Flex Message のヒーロー画像）とラベル，3つのボタン（一致する／一致しない／判定できない）を1つの吹き出しで示す．
- 評価の前に，研究への参加の同意，簡易的な属性（年齢・性別・ボケての利用の程度・アニメやマンガへの親しみ）の質問，軸（形式・属性・媒体）の説明と実例の画像を示す．
- 注意確認の問題：全てのアノテーターと Claude Code が一致した画像に，明らかに誤ったラベル（例：写真に「マンガ」）を付けた問題を，不定期（既定では6〜12問ごとの乱数の間隔）に挟む．
  「一致しない」以外の回答を不合格として記録し，不合格の多い評価者を集計の際に除外できるようにする．
- データの準備（画像の縮小，問題と例の作成，D1 への投入の SQL）と結果の集計（アノテーターごとの一致率）は Python のスクリプトとして用意する．
- LINE の公式アカウントの作成と Cloudflare へのデプロイはユーザーのアカウントで行う必要があるため，手順を README に記し，本作業ではローカル（wrangler dev，LINE の API の模擬）での動作確認までを行う．
