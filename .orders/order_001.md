# Order 001

## ユーザーの指示（原文）

BoketeDBv4lはBoketeから収集した1次データからなるデータベースです．
`@/mnt/d/Bokete_Scraping_v3.2/outputs/BoketeDBv4`

ここから，このデータベースをAIの学習やデータ分析に用いる
アノテーションを付与したデータベースBoketeDBy5を構築することを考えます．

Boketeにはお題画像として,
·現実画像
・アニメのスクリーンショット
・漫画のコマの切り抜き
·文章のお題が書かれた画像
·穴埋め画像
・カルタ画像
があります．

・アニメのスクリーンショット
・漫画のコマの切り抜き
その画像内のキャラクター等の事前知識を必要とするため，
これを区別する必要があります

・文章のお題が書かれた画像
中から文字を検出し,そのうえでボケを生成するプロセスを必要とするため，
これを区別する必要があります

・穴埋め画像
画像中に矩形や円などの記号があり,記号に入る文章をユーザーが考える大喜利で使用します
「東京大学○○学部」，「レ・□ブル」（ユーザーは○○や□に入る文字を大喜利として投稿する
記号の位置を検出したうえでボケを生成するプロセスを必要とするため，
これを区別する必要があります

・カルタ画像
画像中に中にひらがなが書かれた○等の記号があり，そのひらがなから始まる文章をユーザーが考える大喜利で使用します
記号の位置とひらがなを検出したうえでボケを生成するプロセスを必要とするため，
これを区別する必要があります

これらを700万枚のオーダーで処理する必要があり，
APIシステムを用いるのは費用的に現実的ではありません．

これをローカル環境で処理する方法について調べ，いくつかの例で実践し比較してください
比較の際は実際の画像をレポートに追加してください

## 指示の解釈

- 目的は，BoketeDBv4 の約680万枚のお題画像に対し，画像の種類（現実画像，アニメ，漫画，文章のお題，穴埋め，カルタ）を付与する処理を，有料APIを使わずローカルGPU上で実現する方法の調査と比較である．
- 本Orderの範囲は「調査」と「小規模な実践・比較」であり，BoketeDBv5 そのものの構築（全件処理）は含まない．
- 比較する手法の候補は，(1) 画像とテキストの埋め込みによるゼロショット分類（CLIP/SigLIP系），(2) ローカルの視覚言語モデル（VLM）による分類，(3) OCRによる文字検出を用いた規則ベースの判定，とし，処理速度（700万枚に要する時間の見積もり）と分類の妥当性を比較する．
- 正解ラベルは存在しないため，DBのメタデータ（お題タグ，タイトル等）を手がかりに少数の評価用サンプルを抽出し，目視（画像の確認）で正解を付与した小規模な評価集合を作成して比較する．
- レポートには分類結果の例として実際のお題画像を掲載する．
- 学習を伴わない推論中心の実験であるため，機械学習規約のうち学習ループに関する関数仕様は適用せず，ディレクトリ構成，結果の保存規則，可視化，レポートの規約を適用する．
- 6種類の画像は互いに排他的ではない（例: 漫画のコマに空欄がある穴埋め）ため，ボケの生成過程を決める「形式」（normal/text/anaume/karuta）と，事前知識の要否を決める「画風」（photo/anime/manga/illust）の2軸でラベルを定義した．指示の6種類のいずれにも当たらない画像（ゲーム画面，絵画，イラスト等）のために，画風に illust を加えた．比較には2軸を統合した7クラスを主に用いる．
- 評価用の正解ラベルは，抽出した440枚を Claude Code が目視で確認して付与した．
