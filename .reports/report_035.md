# BoketeImageAnnotator の問題の吹き出しの文言の削減

## 1. 概要

BoketeImageAnnotator の問題の吹き出しから，画像の要素の注記「表示されていないものは，画像にないという意味です．」と，問いかけの文「このラベルは画像に合っていますか？」を削除した．また，画像の要素の問題では，これまで空欄，カルタ記号，文字の3項目の定義を常に示していたが，形式・媒体と同じく表示したラベルの項目の定義のみを示すようにした．表示が変わったため，回答に記録する表示の版（`UI_VERSION`）を2から3に上げた．

| 項目 | 内容 |
| :--- | :--- |
| 変更 | `src/messages.ts`（`definitionText`，`taskMessage`），`src/labels.ts`（`UI_VERSION = 3`） |
| 確認 | vitest 14件，型の検査，模擬試験（全項目合格．回答の表示の版が3であることを確認） |
| コミット | `d6dbc4a` |

## 2. 変更の内容

`definitionText` は全ての軸で問題の値を項目に分解し，その項目の定義のみを返す．画像の要素が「空欄・カルタ記号・文字のどれもなし」の場合は空の文字列を返し，吹き出しには定義の行を置かない．LINE の Flex Message は空の文字列の text 要素を受け付けないため，定義と軸の注意は文字列が空でない場合のみ要素に加える．問いかけの文は吹き出しの本文から除いたが，通知やトークの一覧に出る代替テキスト（`altText`）の「…は画像に合っていますか？」は画面の吹き出しには表示されないため残した．画像の要素の注意の1行「形式と関係なく，写っているものを全て挙げる．」は他の項目の説明ではないため残した．

表に，画像の要素の問題の吹き出しに示す文（軸の注意を含む）の文字数を示す．版2では値によらず151字であったが，版3では表示した項目の数に応じて22〜126字となる．

| 画像の要素のラベル | 版2 | 版3 |
| :---: | :---: | :---: |
| どれもなし | 151 | 22 |
| 文字 | 151 | 75 |
| 空欄＋文字 | 151 | 105 |
| 空欄＋カルタ記号＋文字 | 151 | 126 |

## 3. 未解決の論点と次の作業の候補

- 画像の要素の吹き出しには表示していない項目の定義がないため，評価者が「抜けている項目」を判定するには説明の画面で3項目の定義を覚えている必要がある．「どれもなし」の問題で文字の見落としなどの判定の誤りが増えないかを，版3の回答で確かめる必要がある．
- 新しい文言は動作中の `npm run image:tunnel` を再起動するまで反映されない．実際の LINE の画面での表示は未確認である．
- 版2の表示（order_034）で回答された分は版2として記録されている．集計では `export_results.py --ui-version 3` で版3の回答のみに絞れる．
