# 共通の問題（30問）の全員への出題

## 1. 概要

BoketeImageAnnotator に，全ての評価者に同じ問題を同じ順で最初に出題する共通の問題を30問設けた．共通の問題に回答し終えた後は，従来通り回答数の少ない問題から出題する．共通の問題により，評価者の甘さ・厳しさの個人差（report_032 の $` s `$）と評価者間の一致度を推定でき，問題ごとに多数決の正解を得られる．一方，全員が同じ問題のみに回答するとアノテーター×軸のセルあたりの問題の数が少なく，一致率の推定は問題の抽出のばらつきで頭打ちになるため，残りの回答は従来通り問題に分散させる．

| 項目 | 内容 |
| :--- | :--- |
| 選択 | `prepare/select_common.py`（新規．`data/common.sql`，`data/common_tasks.csv`） |
| 出題 | `src/tasks.ts`（`pickCommonTask`），`src/handler.ts`（`nextTask`），`schema.sql` と `migrations/002_add_common_tasks.sql`（`common_tasks` 表） |
| 運用 | 起動のスクリプトが表を作り行を投入する．`npm run image:stats` に共通の問題の回答数を表示する．`npm run image:common:remote` |
| 集計 | `export_results.py`（`common_by_task.csv`，`common_by_rater.csv`，`summary.json` の Krippendorff の α と甘さの標準偏差） |
| 確認 | vitest 14件，pytest 9件，型の検査，模擬試験（全項目合格．共通の問題が2人の評価者に同じ順で最初に出ることを追加），集計と進み具合の表示の試験 |
| コミット | `6f10531` |

## 2. 共通の問題の選び方

アノテーター間の差は値が割れている問題でのみ生じる（report_032）．そこで，同じ画像・軸に2つの値（2者が共有する値と1者のみの値）がある画像を軸ごとに5枚選び，各画像の2つの値をともに問題とした．1者のみの値を付けたアノテーターは軸をまたいで Claude Code，Qwen，生徒モデルが5枚ずつとなるよう巡回させた．これにより，各アノテーターの値は30問中15問（1者のみの値5問，2者が共有する値10問）に現れる．同じ画像の2つの値を同じ評価者が判定するため，2つの値をともに「一致する」とする矛盾（report_032 の媒体の例）も検出できる．説明の実例と注意確認の問題に使う画像は除き，同じ画像の2問が続かない無作為の順（乱数の種0）に並べた．

| 軸 | 画像 | 問題 | 1者のみの値のアノテーター（Claude Code / Qwen / 生徒モデル） |
| :---: | :---: | :---: | :---: |
| 形式 | 5 | 10 | 2 / 2 / 1 |
| 画像の要素 | 5 | 10 | 2 / 1 / 2 |
| 媒体 | 5 | 10 | 1 / 2 / 2 |

## 3. 出題と運用

`nextTask` は，注意確認の問題を出す時でなければ，まず評価者が未回答の共通の問題のうち順（`ord`）が最も早いものを出し，全て回答済みなら従来の回答数の少ない問題を出す．注意確認の問題は従来通り6〜12問ごとに挟むため，共通の問題の間にも入る．共通の問題は既存の `tasks` 表を変えずに別の表 `common_tasks` に持つため，運用中のローカルの D1 の問題と回答はそのまま使える．起動のスクリプトは起動時に表を作り（何度実行してもよい），表が空なら `data/common.sql` を投入して「共通の問題：30 問」と表示する．既に問題に回答した評価者も，未回答の共通の問題から出題される．

## 4. 集計

`export_results.py` は `data/common_tasks.csv` があれば，共通の問題の回答から問題ごとの判定の分布，評価者ごとの「一致する」の割合と甘さ（問題ごとの「一致する」の割合との差の平均），軸ごとと全体の評価者間の一致度を求める．評価者間の一致度は「判定できない」を除いた名義尺度の Krippendorff の α とした．模擬の3人の回答（90件）で集計とファイルの出力を確かめた．

## 5. 未解決の論点と次の作業の候補

- 動作中の `npm run image:tunnel` を再起動するまで共通の問題は出題されない．再起動時の表示「共通の問題：30 問」を確かめる必要がある．
- 共通の問題は全て値が割れた問題であり，全てのアノテーターが同じ値の問題を含まない．甘さの推定は難しい問題の上での値となり，個人差 $` s `$ の推定には `plan_sample_size.py` の模型に合わせた混合効果のロジスティック回帰が必要である（未実装）．
- 1人の回答が30問未満で終わると共通の問題の後半の回答が少なくなる．対面の評価では全員が30問以上に回答するよう時間を確保する必要がある．
- 開発者の動作確認の回答も共通の問題に入る．確認の後に「参加をやめる」で削除する必要がある．
