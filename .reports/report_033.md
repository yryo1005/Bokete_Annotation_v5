# BoketeImageAnnotator のデバッグモードの追加

## 1. 概要

BoketeImageAnnotator に，Worker の変数 `DEBUG` で切り替えるデバッグモードを追加した．デバッグモードがオンのとき，Bot をブロックして解除すると（友だち追加のイベント），その評価者の回答と質問への回答を削除し，新規の参加者と同じくあいさつと同意の確認から始める．オフ（既定）のときは従来通り「おかえりなさい」と続きの問題を示す．

| 項目 | 内容 |
| :--- | :--- |
| 変更 | `src/handler.ts`（`isDebug`，`resetUser`，`onFollow`），`wrangler.toml`（`DEBUG = "false"`） |
| 起動 | `npm run image:tunnel -- --debug`（`.dev.vars` に `DEBUG=true` を書いてもよい） |
| 確認 | 模擬試験（オフとオンのブロックの解除を追加．全項目合格），vitest 12件，型の検査 |

## 2. 処理の内容

`onFollow` は，デバッグモードがオンで評価者の状態が同意の確認の前（`consent`）でなければ，`resetUser` で評価者を初期化してから同意の確認を返す．`resetUser` は参加の取り消し（`withdraw`）と共通の処理であり，回答の削除，問題の回答数（`n_responses`）の戻し，属性・回答数・注意確認の成績・出題中の問題の初期化を1つのバッチで行う．回答も削除するのは，動作の確認の回答が集計に混ざることと，回答済みの問題が再び出題されなくなることを避けるためである．出題の通し番号（`issue_seq`）は初期化しないため，始め直す前の吹き出しのボタンを押しても回答として受け付けない．デバッグモードでは最初に「【デバッグモード】これまでの回答と質問への回答を削除し，新規の参加者として始めます．」と表示する．

`DEBUG` は `true`，`1`，`on`，`yes`（大文字と小文字を区別しない）でオンとなる．`wrangler.toml` の既定は `"false"` であり，Cloudflare へのデプロイの運用ではオフのままとする．

## 3. 動作の確認

模擬試験（`npm run image:simulate`）に次の確認を加え，全ての項目が合格した．

| 確認 | 結果 |
| :--- | :--- |
| オフでブロックして解除 | 「おかえりなさい」と続きの問題が出て，回答の数は変わらない |
| オンでブロックして解除 | デバッグモードの案内と同意の確認が出る |
| オンの初期化 | 状態が `consent`，回答数・注意確認の数が0，属性が空，回答が0件，問題の回答数の合計が削除した回答の数だけ減る |
| オンの始め直し | 同意，属性の質問，説明を経て問題が出る |

確認の過程で，運用中の `npm run image:tunnel` が模擬試験と同じポート8787を使っていたため，模擬試験の Webhook が運用中の Bot に届いた．模擬試験は試験用の署名の鍵を用いるため運用中の Bot は全て401で拒否し，運用のローカルの D1 に模擬の評価者が記録されていないことを確かめた．再発を防ぐため，模擬試験は起動の前にポートが使用中なら止まるようにした（`--port` で別のポートを指定する）．

## 4. 未解決の論点と次の作業の候補

- 実際の LINE でのデバッグモードの動作（ブロックと解除で同意の確認が届くこと）は未確認である．`npm run image:tunnel -- --debug` で起動し，スマートフォンで確かめる必要がある．
- デバッグモードはブロックの解除のたびに回答を削除するため，評価者を集める運用ではオフで起動する必要がある．起動のスクリプトはオンのときに注意を表示する．
- 試行の回答（report_032 の30件）はデバッグモードで始め直すと削除される．残す場合は事前に `export_results.py --source local` で書き出す．
