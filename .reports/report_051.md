# report_051：最終版のアノテーションの構成と精度

## 1. 概要

BoketeDBv5 のアノテーションの最終版の構成をまとめる．対象はパッケージ `Bokete_Annotation_programs_v5.0` の v5.3.0 であり，ボケの段階は v5.2.0 で実行したものである．お題画像とボケ（大喜利）のそれぞれについて，分類の方法，指示（プロンプト）の本文，精度（適合率・再現率・F1）を記す．

精度は新しい推論をせずに，パッケージの出力と既存の目視のラベルから `programs/ex030_final_summary/collect.py` で求め直した．出力は `outputs/ex030_final_summary/` にある．お題文ありの精度は ex025 と ex028 の出力から読み込んだ．目視のラベルは全て Claude Code が付けたものである．

## 2. お題画像のアノテーション

### 2.1 処理の流れ

表2：お題画像の処理の段階．

| 段階 | 処理 |
|---|---|
| list | 画像を列挙する．sha256 が同じ画像は代表の1枚だけを予測する（6,823,270件 → 6,609,511枚） |
| predict | 2つの生徒で形式・属性・媒体の確率を求め，平均する．埋め込みを保存する |
| odai_text | 保存した埋め込みと predict の確率から，お題文ありの生徒の確率を求める |
| verify（既定では行わない） | 形式をお題文と予測した画像に，Qwen3-VL-8B で確認の質問をする |
| finalize | 確率からラベルを決める（2.4節） |
| caption | 媒体が写真のみの画像に，キャプションを付ける（2.5節） |

定義書は第5版である（`docs/label_definition.md`）．属性は複数選択，媒体は原則1つ（合成画像のみ複数）である．形式は属性から「カルタ記号あり → カルタ，空欄あり → 穴埋め，お題文あり → お題文，それ以外 → 通常」の順に導く．

### 2.2 教師ラベル（形式・属性・媒体）

教師は Qwen3-VL-8B-Instruct である．温度0，JSON スキーマによる構造化出力，入力は最大 448×448 画素（200,704 画素）とした．無作為の4万枚と，少ない区分（ゲーム，絵画，カルタなど）の画像約5千枚に，6つの質問（部品）を問い，次の規則で組み合わせた（教師 T_v11．`programs/ex008_label_v4/teacher_v4.py`）．

表3：教師の部品と組み合わせの規則．

| 部品 | 用途 | 組み合わせの規則 |
|---|---|---|
| F_v2（英語） | 形式 | text をお題文とする |
| O_v11_en（英語） | お題文の確認 | 形式がお題文で，確認の質問が偽なら通常にする |
| J_v6（日本語） | 空欄あり，カルタ記号あり（とその文字），お題文・その他の文字 | 空欄・カルタ記号をそのまま用いる |
| X_v10_en（英語） | 読める文字があるか | 文字あり＝J_v6 のお題文かその他の文字，または（X_v10_en かつカルタ記号なし） |
| M_v6（日本語） | 媒体 | CG を除く．媒体が空ならイラストにする |
| P_v8_en（英語） | 美術作品の絵画か | 絵画を置き換え，絵画が真ならイラストを偽にする |

### 2.3 生徒（形式・属性・媒体）

表4：生徒の構成（`docs/method.md`）．2つの確率を平均する．

| モデル | 構成 | 学習 |
|---|---|---|
| 埋め込みの MLP | `google/siglip2-so400m-patch14-384` の画像埋め込み（1,152次元，L2 正規化）→ LayerNorm → 全結合（1,024）→ GELU → Dropout 0.3 → 形式・属性・媒体の出力層 | AdamW，40エポック，検証用で最良のエポック，3 seed の平均 |
| 微調整した SigLIP2-B | `google/siglip2-base-patch16-224` の画像エンコーダに3つの線形の出力層 | 224×224 画素，色の揺らぎの拡張，AdamW（学習率 3e-5），5エポック |

損失は，形式の交差エントロピーと，属性・媒体の2値交差エントロピーの和である．

### 2.4 お題文ありの判定と後処理

お題文ありは，第5版の定義（属性として空欄・カルタ記号と独立に付ける）に合わせて，別の生徒で予測する．

- 教師：Qwen3-VL-32B-Instruct（FP8，最大 802,816 画素）の指示 P3（ex024）．教師ラベルを付けたのは，2.2節の約4.5万枚のうち文字ありの確率が0.3以上の26,577枚である．残りはお題文なしとした．
- 生徒：埋め込み（1,152次元）に形式4・属性3の確率を連結した1,159次元を入力とする MLP（構成は2.3節と同じ）．2値交差エントロピー，AdamW（学習率 1e-3），40エポック．3 seed の平均．
- 判定：形式の確率が最大のものがお題文なら，確率0.05以上でお題文あり．穴埋め・カルタなら0.3以上でお題文あり．通常ならお題文なし．
- 後処理（finalize）：属性・媒体は確率0.5以上を真とする（媒体が空なら最大の項目）．形式の確率が最大の項目から属性を補い，形式は属性から導く．

指示 P3（`programs/ex024_odaibun_attr/qwen_odaibun.py`．出力は `{"has_odai_text": bool}`）：

```text
この画像は大喜利サイト「ボケて」のお題画像です．画像に「お題文」があるかを判定してください．

お題文とは，お題の投稿者が回答者に向けて書き加えた，大喜利の題となる文です．次のようなものです．
- 問い（「〜とは？」「〜なのはなぜ？」「最初に放った一言とは？」）
- 指示（「〜してください」「〜しろ」）
- 題目の句（「こんな〜は嫌だ」「〜あるある」「〜の共通点」「〜な事」）．題目の後に例が列挙され，最後の項目が空欄のものを含む
- 状況の設定（「〜したら…」「〜なのに」）や短い筋書き
- ボケてのテンプレートや無地の背景，画像の上下の帯に投稿者が書いた主題の文（台本，手紙の書き出し，題名など）

次のものはお題文ではありません．
- 空欄を含む文章のまとまり（段落，説明文，記事，字幕やテロップ，歌詞，引用，台詞）．空欄のない文が含まれていても，同じまとまりの一部ならお題文ではありません
- 空欄（□，○○，？，空の枠，空の吹き出しなど）を含む文そのもの．空欄とは別の文として問い・指示・題目・状況の文がある場合だけ，お題文ありとします
- 元の素材にある文字：テレビの字幕やテロップ，看板，ポスター，本・CD・DVD の表紙，商品，ウェブの記事，SNS や アプリの画面，ゲーム・アニメ・漫画の台詞，歌詞，人物やものの説明文
- 絵の中の吹き出しに書かれた登場人物の台詞
- ひらがな1文字のカルタの記号，ロゴ，透かし，署名

判断の手順：まず画像中の文字を，投稿者が書き加えたものと元の素材にあるものに分けます．次に，投稿者が書き加えた文字から，空欄を含む文章のまとまりを除きます．残った文字に問い・指示・題目・状況の文があればお題文ありです．迷う場合はお題文なしとします．
JSON のみを出力してください．
```

### 2.5 写真のキャプション

媒体が写真のみの画像（3,371,140枚）に，Qwen3-VL-30B-A3B-Instruct-FP8 で日本語の1文を付ける．入力は最大 448×448 画素，温度0，最大64トークン，vLLM の `VLLM_BATCH_INVARIANT=1`（再現性）とした．句読点を「、」「。」にそろえ，壊れた出力には `caption_ok`＝偽を付ける．指示の本文は次のとおりである．


### 2.6 精度

## 3. 大喜利（ボケ）のアノテーション

### 3.1 発話の型と画像外の知識

定義書は第3版である（`docs/boke_label_definition.md`）．発話の型の6区分は，セリフ（S），心の声（M），ツッコミ・呼びかけ（T），状況の説明・物語（N），名付け・見立て（L），回答（A）である．3区分は，登場人物の言葉（S，M），外からの言葉（T，N，L），回答（A）とする．画像外の知識は，「画像にも画像中の文字にも示されていない特定の事物の知識が，面白さの理解に必要か」の2値である．

判定は，お題画像とボケの文を入力とする分類器で行う．

- モデル：Qwen3-VL-4B-Instruct の全ての線形層にランク16の LoRA を付ける．言語モデルの最終層の，入力の最後のトークンの隠れ状態に，発話の型（6区分）と画像外の知識（2値）の出力層を付ける．生成はせず，1回の順伝播で判定する．
- 学習：二段階で行った．第1段階では，Qwen3-VL-32B（FP8）の教師ラベル34,634件で学習した．第2段階では，目視のラベル931件で微調整した．教師のラベルだけでは，教師の偏り（セリフをツッコミとするなど）を受け継ぎ，6区分が0.55にとどまった．
- 判定：発話の型は確率が最大の区分とする．画像外の知識は確率0.5以上を「はい」とする．回答も分類器が判定する（教師ラベルでは，形式が穴埋め・お題文のボケを規則で回答とした）．
- 推論：LoRA を重みに統合する．同じお題のボケでは，お題画像とお題の部分の計算を1回にまとめて共有する（プレフィックスのキャッシュ）．速さは約345件/秒で，全件は約3.1日である．

分類器への入力の文（`bokete_annotation/boke.py`．お題画像は長辺448画素以下）：

```text
大喜利サイト「ボケて」のお題画像（形式：{形式}）に投稿されたボケ：「{ボケの文．改行を空白にし，200文字まで}」
```

教師の指示 one_kt_cap（Qwen3-VL-32B．`programs/ex015_boke_labels_v3/teacher.py`）は次のとおりである．お題の形式・媒体・画像中の文字の有無と，写真のキャプションを文で加える．

```text
これは大喜利サイト「ボケて」のお題画像と，それに投稿されたボケです．
お題の形式：通常（画像に自由に一言を付ける）
お題画像の媒体：{媒体}．画像中の文字：{あり／なし}
お題画像の説明：{写真のキャプション}
ボケ：「{ボケの文}」

1. voice：ボケが誰の視点の，どのような言葉か．次の手順で1つ選ぶ．
   (1) ボケが名詞句（体言止め）で，画像全体や写っている物に名前・題・例えを付けている（「〜の時の俺」「〜界の〜」を含む） → L
   (2) 話し手が画像の中の人物・動物・物（擬人化を含む）で，声に出している（呼びかけ，返事，叫び，掛け合い） → S
       心の中の考え，独り言 → M（迷う場合は S）
   (3) 話し手が画像の外の人で，画像の出来事や前後の状況を説明する文 → N
       画像を見て言う感想・指摘・ツッコミ，画像の人物への呼びかけ → T

2. 画像外の知識を，次の手順で答える．
   referent：ボケの面白さが依存している事物の名前．なければ空文字．
   referent_type：referent の種類を次から1つ選ぶ．固有名詞でなければ general とする．
     work：特定の作品・キャラクター・番組・映画・ゲーム・歌・CM・有名な台詞やキャッチコピー
     person：実在の特定の人物・団体
     product：特定の商品・ブランド・店
     place：特定の地名と，その土地の印象
     event：特定の出来事・ニュース・流行語・ネットの定型
     bokete：ボケての機能や慣習
     general：普通名詞（一般の物，道具，料理，スポーツ，法律，職業，ジャンル，生活の行事，遊び），ことわざ，慣用句
     none：依存する事物がない
   in_image：referent が画像に写っている，画像中の文字で名指しされている，または画像に写っているキャラクターと同じ作品の登場人物・設定か．
   necessary：referent を知らない人には，一般の日本語の語彙と常識があってもボケの面白さが分からないか（名前が背景にすぎないなら false）．

JSON のみを出力してください．
```

出力は JSON スキーマで `voice`（S，M，T，N，L），`referent`，`referent_type`，`in_image`，`necessary` に制約した．画像外の知識は，`referent_type` が固有の種類（work，person，product，place，event，bokete）で，`in_image` が偽で，`necessary` が真のときに「はい」とする．

### 3.2 制約の順守と画像中の文字への依存

- カルタ：ボケの書き出しの音（漢字・カタカナは読みに変換）が，札のかな（そのお題のボケの書き出しの最頻値）と一致するかを判定する．漢字で始まるボケは順守とみなす．
- 穴埋め・お題文：同じお題の他のボケ（最大50件）のうち，ruri-v3-310m の文の埋め込みが最も似た5件とのコサイン類似度の平均を得点（`compliance_score`）とする．しきい値は設けていない．
- 画像中の文字への依存（`uses_image_text`）：形式が穴埋め・お題文なら真とする規則である．

### 3.3 精度

正解は，検証データ620件（調整用308件，最終評価用312件）の合意ラベルである．合意ラベルは，元のラベルと，元のラベルを見ずに付け直したラベルの不一致を裁定したものである．予測は，パッケージのコードで検証データを推論した結果（ex019 の `verify_eval_pred.csv`）である．

## 4. 考察

お題画像の形式・属性・媒体は，写真・文字あり・マンガ・通常・カルタで F1 0.97 以上であり，実用上十分である．精度が低いのは，次の3つである．

- 絵画（少ない区分の評価用データで F1 0.79）
- イラストとアニメ・ゲームの境界（F1 0.74〜0.90）
- お題文あり（第6版の正解で F1 0.79）

お題文ありの再現率の低さは，第6版で定義を広げた（元の素材の字幕の問いを含めた）ことによる．第5版の定義では F1 0.83 である．

ボケの発話の型は，3区分で F1 0.86，6区分で 0.71 である．6区分のうち心の声とツッコミは，人の判断の揺れも大きい．画像外の知識は F1 0.69 で，目視の再現性（0.85）との差が最も大きい．主な誤りは，有名な台詞・歌詞・ネットの定型の引用の見逃しと，画像に写っている作品の登場人物の名前を画像外とする誤検出である．

全ての正解は Claude Code の目視であり，人による評価は行っていない．目視の判断者内の再現性は，お題文ありで97%（report_048），ボケの3区分で F1 0.93 である．
